# تاریخ اعتبار استراتژی و جزئیات اهداف

## درخواست مالک پروژه

در ۲۰۲۶-۱۱-۲۱ مالک پروژه خواست تاریخ اعتبار از/تا در ایجاد و ویرایش استراتژی
و در پنل جزئیات استراتژی و هدف نمایش داده شود. در جزئیات هدف نیز واحدهای
سازمانی مرتبط از تخصیص‌های موجود نمایش داده می‌شوند.

این درخواست فقط محدودیت تاریخ‌های استراتژی و حذف سازمان‌ها از پنل جزئیات هدف
را در تصمیم‌های قبلی اصلاح می‌کند. استراتژی همچنان دستهٔ ریشه است، نوع هدف و
تخصیص سازمانی ندارد و فقط دو تب اطلاعات کلی و مستندات را نگه می‌دارد.

## قرارداد ذخیره و نمایش

- فیلدهای موجود `validFrom` و `validTo` روی جدول و DTO فعلی `objective` استفاده
  می‌شوند. مهاجرت، جدول یا API جدیدی لازم نیست؛ null همچنان معتبر است.
- Create و Update هر دو نوع، ترتیب تاریخ‌ها را اعتبارسنجی و مقدارشان را ذخیره
  می‌کنند. تاریخ نامعتبر، Save و خروج بدون تصمیم کاربر را مانند سایر فرم‌ها
  کنترل می‌کند. نمایش تاریخ‌ها شمسی و بدون ساعت است و API مقدار میلادی می‌گیرد.
- خلاصهٔ سازمان‌ها فقط برای هدف، از API موجود همان پروفایل بارگذاری می‌شود؛
  ردیف حذف‌شده نمایش داده نمی‌شود. بارگذاری، خطا و لغو درخواست ردیف قبلی رعایت
  می‌شود. این خلاصه مسیر ویرایش یا ذخیرهٔ مستقل ندارد.
- Guardهای `OBJECTIVE` و `ORGANIZATION` و تراکنش فعلی Create/Update حفظ می‌شوند؛
  خواندن ساختار، اعتبارسنجی، ذخیرهٔ تاریخ و مستندات و CENTRAL Revision در همان
  مرز محافظت‌شده باقی می‌مانند. قواعد والد، فرزند و تخصیص سازمانی عوض نمی‌شوند.

## مجوز بررسی این درخواست

مالک پروژه صریحاً خواست خطاهای ایجاد کنترل و کنترل سطح کل توسط عامل آزمایش
شوند. آزمون اختیاری `GovernanceCatalogOracleVerificationTest` فقط با فعال‌سازی
صریح و نام schema موقت با پیشوند `GRCPC_V_` اجرا می‌شود. داده‌های سامانهٔ جاری
برای این بررسی تغییر نمی‌کنند؛ این مجوز، محدودیت عمومی آزمون‌ها در تحویل‌های
دیگر را تغییر نمی‌دهد.

## خطای ایجاد کنترل و نتیجهٔ بررسی

- خطای ایجاد کنترل در درخواست واقعی MVC روی Oracle بازتولید شد: سیاست محافظت
  پروفایل، عبارت `PreAuthorize` را داخل تراکنش و بدون آرگومان‌های فرم دوباره
  ارزیابی می‌کرد؛ فراخوانی `initialSubprocess()` روی متغیر خالی خطا می‌داد.
  شرط CONTROL در کنترلر حفظ شد و شرط CONTROL + PROCESS برای ایجاد همراه
  زیرفرآیند، پیش از خواندن/تغییر موجودیت‌ها به callback محافظت‌شدهٔ Create منتقل شد.
  Guardهای موجود CONTROL و PROCESS و ترتیب لغوی سایر Guardها حفظ می‌شوند.
- در فرم کنترل، مقدار Select از `selectedOption.value` خوانده می‌شود؛ بازگشت
  به گزینهٔ خالی نباید متن برچسب را به‌عنوان مقدار enum به API بفرستد.
- ایجاد کنترل سطح کل با کد جدید موفق بود. همان پیام تصویر با کد تکراری، حتی
  پس از حذف نرم، بازتولید شد؛ کد رزروشده و بازیابی رکورد قبلی طبق قرارداد موجود
  حفظ شدند. پیام کد تکراری اکنون ترجمه دارد و کد موردنظر را نشان می‌دهد.
- `mvnw.cmd -o -Dskip.ui=true -Dtest=GovernanceCatalogOracleVerificationTest test`:
  شش آزمون موفق؛ ایجاد/خواندن کنترل و کنترل سطح کل، شرط مجوز زیرفرآیند، کد
  تکراری/حذف نرم/بازیابی، ذخیره و ویرایش تاریخ استراتژی، و رد بازهٔ نامعتبر.
- `npm run typecheck`، `npm run lint` و بررسی ایستای diff موفق بودند.
  اجرای هم‌زمان تراکنش‌ها و بررسی ظاهری مرورگر انجام نشدند.
